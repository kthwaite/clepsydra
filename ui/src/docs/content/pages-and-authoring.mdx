A Folio is an ordinary Markdown page in the vault. Clepsydra gives each page a
stable frontmatter identity while letting its vault-relative path change as you
organize it.

## Prerequisites

- Run Clepsydra against an initialized vault and open the web application.
- Open the command console with `Command+K` on macOS or `Ctrl+K` elsewhere.
- Use an editable Folio when you need the organization controls. A page opened
  through `/pages/<vault-relative-path>` is restored as a tab in `/workspace`.

## Workflow

### Create a Folio

1. Run **Inscribe new folio** (`app.inscribe`) from the command console, or use
   `Command+N` on macOS and `Ctrl+N` elsewhere.
2. Choose a **Kind**, optionally choose a **Project**, enter the required
   **Title**, and add any tags.
3. Check the `REF` path preview, then choose **commit to archive**.

New Folio filenames have the canonical shape
`<yyyymmdd>.<title-slug>.<short-id>.md`. The selected Kind chooses the top-level
folder and Project adds a subfolder, so a NOTE in project `atlas` can be created
as `notes/atlas/20260812.field-notes.A1b2C3d4.md`. The title slug is capped and
is not the page's identity.

Every page has a UUID in TOML frontmatter as `id`. That ID remains the page's
identity when its path changes. Changing the displayed title updates
frontmatter; it does not automatically rename the existing file. New
frontmatter can also contain `title`, `type`, `project`, `tags`, `aliases`,
`created_at`, and `updated_at`.

Creation writes the page at the projected path, then declares the selected Kind
and Project. If that declaration fails, the created page still opens rather
than being hidden by the intake dialog.

### Use Kind and Project projection

The Document details rail shows **Kind**, **Project**, and **Path**. Assigning a
Kind writes the `type` frontmatter field; the unrelated frontmatter key `kind`
is an ordinary property. Assigning a Project writes `project`. Either assignment
can move the same file so the folder follows its declared metadata.

| Kind | Canonical folder |
| --- | --- |
| `NOTE` | `notes` |
| `PROJECT` | `projects` |
| `JOURNAL` | `journals` |
| `TODO` | `todos` |
| `QUOTE` | `quotes` |
| `BOOK` | `books` |
| `CAPTURE` | `captures` |
| `CODE` | `code` |
| `PERSON` | `people` |
| `TASK` | `tasks` |
| `CYCLE` | `cycles` |
| `AI_CONVERSATION` | `conversations` |

Without a declared `type`, Clepsydra infers Kind from the top-level folder and
otherwise falls back to NOTE. Missing metadata is conservative: no declared
Kind keeps the current top-level folder, and no declared Project keeps the
current subfolder. Explicitly clearing Project removes its subfolder. A
successful projected move keeps the filename and updates links as one planned
mutation.

### Move or rename a page

1. In an editable Folio, open **Manage paths** under **Organization**.
2. Choose **Move or rename page**.
3. Enter the complete vault-relative destination, including `.md`.
4. Choose **Preview move**, review the server-generated file operations and
   link edits, then choose **Move page**.

The destination must be inside the vault and must not already exist. The active
tab follows a successful move. Saving is flushed before Clepsydra prepares the
preview.

The preview is a snapshot of the file operations and link edits calculated when
you requested it. Confirmation resubmits the displayed source, destination, and
rewrite policy; it does not submit that calculated plan. The server replans
against the current vault before applying the mutation, so the actual affected
set can differ from the snapshot or the operation can conflict. Re-preview
immediately before confirming, especially after any other vault activity.

### Create, move, or delete folders

Open **Manage folders** in the same **Manage paths** panel.

- **Create** accepts a vault-relative folder such as `notes/research` and does
  not require a preview.
- **Move or rename** requires a source folder and destination. Choose
  **Preview folder move**, review every planned file and text edit, then choose
  **Move folder**.
- **Delete** is permanent and has no server preview. Select the folder, type
  its exact path to confirm, and leave **Delete contents recursively**
  unchecked for an empty folder. Checking it deletes the folder's contents
  too. Recursive folder deletion does not check or rewrite inbound links.
  Deleted folder pages do not enter the Rubbish Bin, so surviving Folios can
  retain unresolved references.

### Archive, restore, or permanently delete a page

Choose **Archive Page** from **Manage paths**. Clepsydra saves the current
Folio first, then moves the page into the Rubbish Bin. The page disappears
from normal views; inbound links remain byte-identical and become unresolved.
Archiving closes every open tab for that page.

Open **Rubbish Bin** from the desktop rail, mobile roots, or Command Palette.
Select an item to inspect its original path, page ID, Kind, deletion time, and
read-only stored-body preview. **Restore** returns it only to its original
path. If that path is occupied, move or rename the active page and retry; the
retained item stays in the bin. Successful restoration preserves the original
page ID and content, so inbound links resolve again.

**Delete permanently** removes one retained item and cannot be undone.
**Empty Rubbish Bin** requires a stronger confirmation, processes the current
retained-item snapshot in order, and reports every success or failure. Failed
items remain available for inspection and retry.

## Failures and conflicts

- Intake refuses a blank title. Invalid paths, unknown Kinds, invalid Project
  slugs, and existing destinations are rejected.
- A page-create collision returns a conflict and does not overwrite the
  existing file. A Kind/Project declaration can fail after intake creation;
  the new page remains at its created path.
- Moving a missing source fails. Moving to an existing destination fails rather
  than replacing it.
- Move preview first flushes the current Folio. Files can change after a
  preview, so move confirmation replans and may conflict; re-preview after a
  failure.
- Archive also flushes the current Folio. If saving or archival fails, no tab
  closes and the page remains active. Archive does not rewrite or remove
  backlink markup.
- Restore conflicts retain the item. Move an active page occupying the
  original path, or refresh the Rubbish Bin if retained bytes changed.
- Folder deletion cannot be previewed. Non-recursive deletion fails for a
  non-empty folder. Recursive deletion is intentionally destructive, performs
  no inbound-link safety check, and performs no link rewriting.

## Privacy

Filenames, folder names, vault-relative paths, and TOML frontmatter are
plaintext. They can reveal titles, projects, Kinds, tags, aliases, timestamps,
and page identity even when the Markdown body is protected. Use neutral names
and metadata when those details are sensitive; protecting a body does not hide
its location or organization.
