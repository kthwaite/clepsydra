The installed Rust binary is `clep`. From a source checkout, substitute
`cargo run --bin clep --` for `clep` in the examples below. `clep --help` and
each command's `--help` are the authoritative syntax; `clep --version` prints
the package version.

Commands return `0` on success. Clap rejects an unknown command, unknown option,
missing required argument, or invalid option value before dispatch: it prints a
usage error to stderr and returns `2`. Errors after successful parsing are
printed as `Error: <message>` to stderr and return `1`, except where a command
documents a more specific status below. Commands that open the vault use the
normal application-config lookup and build or open the vault index; they do not
require `clep serve` unless stated otherwise.

## Application config lookup

Commands that need application config check, in order:

1. `./config.toml`
2. `$XDG_CONFIG_HOME/clepsydra/config.toml`
3. `$HOME/.config/clepsydra/config.toml`

If no candidate exists, the command fails. Settings-backed commands then merge
built-in defaults, that file, and `CLEPSYDRA__...` environment overrides.
`clep new` is the exception: it reads `[vault].root` directly from the selected
file, requires that key, does not apply a `CLEPSYDRA__VAULT__ROOT` override or
the normal `./vault` default, and resolves any relative value from the config
file's directory without `~` expansion. See [Configuration](/docs/configuration).

## Command summary

| Command | Required input and notable options |
|---|---|
| `clep init` | `[PATH]`, default `.` |
| `clep new` | `<TITLE>`, optional `-b, --body <TEXT>` |
| `clep backup` | `--destination <DIRECTORY>` |
| `clep config` | nested `show`, `path`, or `create` command |
| `clep env` | no options; placeholder |
| `clep doctor` | `--json`, `--strict`, `--full` |
| `clep serve` | `--tls`, `--port <PORT>` |
| `clep lsp` | no options |
| `clep mcp` | `--allow-remote` |
| `clep todo` | words or stdin; optional `--due`, `--scheduled`, `--priority` |
| `clep open-url` | `<URL>`, optional `--print` |
| `clep relabel` | optional `--dry-run` |
| `clep migrate` | optional `--write`; dry run by default |
| `clep cas` | nested `backfill` or `rebuild` command |
| `clep codes` | nested `migrate` command |
| `clep register-url` | optional `--obsidian`; macOS only |
| `clep grep` | `<QUERY>`, `-n/--limit <N>` (default `20`), `--raw`, `--json` |
| `clep tree` | optional `--json` |
| `clep version` | no options |

Every command accepts `-h, --help`.

## `clep init`

```text
clep init [PATH]
```

Initializes `PATH`, defaulting to the current directory. A missing path is
created. The command creates `.clepsydra/config.toml`,
`.clepsydra/templates/`, and `_attachments/`, then prints the initialized path.
It fails rather than replacing an existing `PATH/.clepsydra` directory.

```bash
clep init ~/vault
```

## `clep new`

```text
clep new [OPTIONS] <TITLE>
  -b, --body <TEXT>
```

Creates a Markdown page in the configured vault. The title is stored in
frontmatter and drives canonical path generation. `--body` supplies optional
initial body text. The vault's `.clepsydra/config.toml`
`vault.default_page_folder` selects the destination folder.

This command requires a selected application config whose file explicitly
defines a non-empty `[vault].root`; unlike Settings-backed commands, it ignores
`CLEPSYDRA__VAULT__ROOT`, does not fall back to `./vault`, and does not expand
`~`. It fails for missing or invalid config, a missing root key, an invalid
vault, invalid title/path generation, or a colliding page instead of overwriting
an existing file.

```bash
clep new "Daily Log"
clep new "Inbox" --body "- [ ] follow up"
```

## `clep backup`

```text
clep backup --destination <DIRECTORY>
```

Requires application config and a readable vault. The destination directory is
created when needed. The command writes a timestamped
`clepsydra-backup-YYYYMMDDTHHMMSSZ.tar` and prints its path. It does not follow
symlinks, excludes the rebuildable index cache and live feed database sidecars,
and places a consistent feed-database snapshot in the archive when one exists.
A partial archive is removed after a failed write. Invalid vault roots,
unreadable files, feed-snapshot failures, destination conflicts, and filesystem
errors return `1`.

```bash
clep backup --destination ~/Backups
```

## `clep config`

```text
clep config <COMMAND>
```

This parent command requires one nested command. It operates only on application
config, never `<vault>/.clepsydra/config.toml`.

## `clep config show`

```text
clep config show [--origin]
```

Prints the selected config bytes verbatim to stdout, adding no heading or
newline. With `--origin`, unchanged stdout remains pipe-safe while
`Origin: <selected path>` is written to stderr. Missing config or read failures
return `1`.

```bash
clep config show
clep config show --origin > selected-config.toml
```

## `clep config path`

```text
clep config path [--trace]
```

Prints only the selected path plus a newline. `--trace` additionally writes the
candidates actually considered to stderr, stopping at the selected file. Missing
config returns `1`.

```bash
clep config path --trace
```

## `clep config create`

```text
clep config create
```

Creates a non-empty, fully commented template at
`$XDG_CONFIG_HOME/clepsydra/config.toml`, falling back to
`$HOME/.config/clepsydra/config.toml`. Parent directories are created. The
command prints the new path and refuses to overwrite any existing file.

## `clep env`

`env` is a placeholder. It prints `env command not implemented yet` and returns
`0`; it does not inspect or validate the environment yet.

## `clep doctor`

```text
clep doctor [--json] [--strict] [--full]
```

Runs checks grouped under server config, server, vault, index, CAS, and runtime.
Checks report `OK`, `WARN`, `ERR`, `INFO`, or `SKIP`.

- `--json` writes machine-readable JSON instead of the human report.
- `--strict` makes any warning produce a failing exit status.
- `--full` enables expensive checks such as CAS statistics.

The exit status is `0` when no check fails, and `1` when a check fails or a
warning occurs under `--strict`. Unlike most config-dependent commands, doctor
reports missing or broken prerequisites as checks rather than aborting at the
first one.

```bash
clep doctor
clep doctor --strict --full
clep doctor --json > doctor.json
```

## `clep serve`

```text
clep serve [--tls] [--port <PORT>]
```

Starts the HTTP API and embedded frontend. It requires application config and a
usable `[vault].root`. The configured `[server]` defaults are host `localhost`,
port `3000`, and `dev_mode = false`. `--port` replaces the effective configured
or environment port. `--tls` only turns TLS on; it never downgrades a config
where TLS is already enabled.

When TLS is active, Clepsydra uses `[server.tls].cert_path` and `key_path` only
when both are set. Otherwise it provisions and caches localhost certificates
with `mkcert`; missing `mkcert`, unreadable certificate files, vault/index
startup failures, and bind errors fail startup.

There is no built-in API login, bearer token, or API key. Loopback reachability
is the default trust boundary. If `server.host` exposes the service elsewhere,
use a separately controlled network boundary and a certificate valid for the
client-visible hostname.

```bash
clep serve
clep serve --tls
clep serve --tls --port 3443
```

After startup:

- `GET /api/openapi.json` returns the OpenAPI document.
- `GET /api/docs` opens Swagger UI.
- [API Reference](/docs/api-reference) inventories every public operation.

## `clep todo`

```text
clep todo [OPTIONS] [WORDS]...
  --due <YYYY-MM-DD>
  --scheduled <YYYY-MM-DD>
  --priority <A|B|C>
```

Captures one unchecked Markdown Todo in today's journal through the configured
local Clepsydra server. Provide the Todo text as positional words, or omit the
words to read text from stdin through EOF. Positional words take precedence over
stdin when both are present. The command normalizes all multiline input and
extra whitespace to one Todo line.

The optional `due` and `scheduled` values must be real dates in exact
`YYYY-MM-DD` form. `priority` is `A`, `B`, or `C`. When properties are present,
they are written in the order due, scheduled, priority.

```bash
clep todo Buy oat milk
clep todo "Call the dentist"
printf 'Review notes\n' | clep todo
clep todo Ship release --due 2026-09-01 --scheduled 2026-08-30 --priority A
```

`clep serve` must be running with the same selected configuration, and the
configured `server.host` must be a loopback host such as `localhost`,
`127.0.0.1`, or `::1`. Bind-all values such as `0.0.0.0`, `::`, and `[::]`
count as non-loopback and are refused. TLS mode and certificate paths come from
that selected configuration, so the command trusts the same local certificate
as the server. On success, it prints `Captured Todo in <journal path>`.

## `clep lsp`

Starts the standalone, read-only language server on stdio. It resolves a vault
from the editor workspace's `.clepsydra` ancestor, falling back to application
config. It does not require the HTTP server and can run beside `clep serve`.
Stdout is reserved for LSP framing; diagnostics and tracing go to stderr. If no
workspace vault or configured vault can be resolved, initialization fails.

See [LSP](/docs/lsp) for client setup.

## `clep mcp`

```text
clep mcp [--allow-remote]
```

Starts an MCP stdio proxy to the HTTP API selected by application config. A
matching `clep serve` must already be running. By default MCP refuses a
non-loopback `[server].host`; `--allow-remote` acknowledges that target. TLS mode
and certificate paths come from the same config. Connection failures include a
server-start hint, and TLS setup fails when the configured or generated
certificate cannot be trusted or read.

MCP sends no bearer token, password, or client credential; anyone who can drive
the MCP host or reach the API is inside the trust boundary.

```json
{ "mcpServers": { "clepsydra": { "command": "clep", "args": ["mcp"] } } }
```

See [MCP](/docs/mcp) for the tool inventory and remote-host cautions.

## `clep open-url`

```text
clep open-url [--print] <URL>
```

Translates a `clepsydra://` or compatible `obsidian://` URL into the configured
server's HTTP(S) deep-link URL. On macOS it asks the default browser to open that
URL. On other platforms, and whenever `--print` is present, it prints the URL
instead. `--print` only translates; it does not contact the server.

The command requires application config. Invalid config and a failed macOS
`open` process return `1`; server availability is observed later by the browser.

```bash
clep open-url "clepsydra://page/Alpha%20Project"
clep open-url "obsidian://open?vault=brain&file=Note" --print
```

## `clep relabel`

```text
clep relabel [--dry-run]
```

Opens the configured vault and fully derived index, then renames authored pages
to the canonical `yyyymmdd.slug.shortid.md` scheme and rewrites inbound
wikilinks. Without `--dry-run`, changes are applied. `--dry-run` prints the plan
without filesystem changes. The summary reports renamed and skipped counts;
config, index, path, rewrite, or filesystem failures return `1`.

Run a vault backup or commit before applying a large relabel:

```bash
clep relabel --dry-run
clep relabel
```

## `clep migrate`

```text
clep migrate [--write]
```

Sweeps the configured vault for legacy `---` YAML frontmatter. The default is a
dry run; `--write` converts candidates to `+++` TOML. Conversion preserves the
page ID, fields, and body but cannot preserve comments inside YAML frontmatter,
so commit or back up the vault first.

The command prints each conversion and warning. It returns `0` when there are no
warnings and `1` when any warning is reported, even if other pages converted.
Config or vault-open failures also return `1`.

```bash
clep migrate
clep migrate --write
```

## `clep cas`

```text
clep cas <COMMAND>
```

This parent command requires one nested command. It maintains the vault's
content-addressed blob store (the CAS).

## `clep cas backfill`

```text
clep cas backfill [--write]
```

Sweeps the configured vault for archive pages whose `[archive] blobs` array
still holds legacy hash-only string entries, and types each one as a
`{ hash, type }` table by looking up its content type in the resolved
`cas.db`. The CAS path is `[archive].cas_path` from the vault's
`.clepsydra/config.toml`, `~`-expanded, the same resolution `clep serve` and
`clep doctor` use. The default is a dry run; `--write` applies the change.

A hash absent from `cas.db` is left as a string entry and reported as a
warning; a page whose frontmatter cannot be fully read (merge conflict
markers, malformed TOML) is reported and left untouched — the sweep never
rewrites what it did not fully read. Entries already typed are left alone.
`.clepsydra/` (including the rubbish bin) is never swept; legacy string
entries there are tolerated indefinitely.

The command prints each page it updates (or would update) and every warning.
It returns `0` when there are no warnings and `1` when any warning is
reported, even if other pages updated. Config, vault-open, or `cas.db`-open
failures also return `1`.

```bash
clep cas backfill
clep cas backfill --write
```

## `clep cas rebuild`

```text
clep cas rebuild [--write]
```

Recreates `cas.db` from disk truth: the CAS is gitignored and derived (ADR
0005), so a freshly synced or corrupted device rebuilds it from the blob
files under `[archive].cas_path` plus a vault-wide scan of live pages and
rubbish items. For each blob file found: size comes from the file; content
type comes from the scan's `{hash, type}` frontmatter entries (a snapshot
hash defaults to `text/html`), falling back to `application/octet-stream`
and reporting the hash as untyped when no page named a type for it;
`ref_count` is the number of live pages and rubbish items whose frontmatter
references the hash, or `0` (unreferenced, GC-eligible once old enough) when
none do. A hash referenced in frontmatter with no backing blob file is
reported missing. `created_at` resets to now for every row, which only
delays a later `gc` — never triggers one early.

The default is a dry run that only computes the report; `--write` applies it
inside one transaction, replacing every row in `blobs`. `--write` also clears
`rubbish_archive_releases`: the recount above already credits every rubbish
item still present on disk with its references, so the ledger of
already-released items would otherwise cause their next purge to skip
decrementing and leak those refs. Clearing it makes each present rubbish
item's next purge decrement exactly once, matching the recount.

The command prints scan warnings, then each untyped and missing hash, then a
summary line. It returns `0` when there are no missing files and no scan
warnings, and `1` otherwise, even if rows were written. Config or vault-open
failures also return `1`.

```bash
clep cas rebuild
clep cas rebuild --write
```

## `clep codes`

```text
clep codes <COMMAND>
```

This parent command requires one nested command. It hosts utilities for the
Task/Cycle petname code scheme (`TSK-brave-finch-7q3zd` / `S-calm-heron-2xm9p`,
ADR 0003).

## `clep codes migrate`

```text
clep codes migrate [--write]
```

One-time migration from the legacy sequential code scheme (`TSK-0072`, `S-3`)
to petname codes. Opens the configured vault and fully derived index directly
— **stop `clep serve` first**, or its own in-memory index falls out of sync
with the renames.

Two passes. First, every TASK or CYCLE page whose filename stem is not
already a valid petname code is renamed to a freshly minted one; inbound
`[[wikilinks]]` are rewritten by the move planner, the same mechanism `clep
relabel` uses. Second, every plain-text legacy token (`TSK-0072`, `S-3`) is
rewritten vault-wide, including inside frontmatter values such as
`cycle = "S-3"`, which the move planner does not touch — using the map of
legacy code to newly minted code built by the first pass. A legacy token with
no corresponding renamed page (for example a typo, or a code for a page that
no longer exists) is left as-is and reported as a warning. A page with merge
conflict markers, or an encrypted page, is skipped with a warning rather than
rewritten. The default is a dry run — codes are minted and the full plan is
reported, but nothing on disk changes; `--write` applies it.

A page that fails to rename, or whose destination already exists, does not
abort the run: it is warned about and left untouched for a later run to
retry, and its legacy code is correspondingly left unrewritten (and warned
about) wherever it's mentioned in prose elsewhere, rather than being
rewritten to a code that was never actually created.

This is a one-time, **irreversible clean break**: after `--write` runs, no
code in the legacy format is recognized anywhere in Clepsydra, and there is
no alias mapping old codes to new ones. A legacy code recorded outside the
vault (an external link, a chat log, a paper notebook) no longer resolves to
anything. Commit or back up the vault first.

The command prints each rename, each rewrite with its token count, and every
warning, then a summary line. It returns `0` when there are no warnings and
`1` when any warning is reported, even if other pages were renamed or
rewritten. Config or vault-open failures also return `1`.

```bash
clep codes migrate            # dry run
clep codes migrate --write    # rename and rewrite in place
```

## `clep register-url`

```text
clep register-url [--obsidian]
```

macOS only. Builds and installs
`~/Applications/Clepsydra URL Handler.app` and registers `clepsydra://` to invoke
this binary's `open-url` command. `--obsidian` also claims `obsidian://`, which
competes with Obsidian when installed. Non-macOS execution and app compilation,
installation, or Launch Services failures return `1`.

## `clep grep`

```text
clep grep [OPTIONS] <QUERY>
  -n, --limit <N>  # default: 20
      --raw
      --json
```

Searches the configured vault's full-text index and ranks results by relevance.
The query is a literal phrase by default. `--raw` passes it to FTS5, enabling
operators such as phrases, `AND`, `OR`, `NEAR`, and prefix `*`. `--json` emits
machine-readable output instead of styled text. Invalid raw FTS5 syntax, config,
vault, or index failures return `1`.

```bash
clep grep "spaced repetition"
clep grep chloroplast --limit 5
clep grep "foo OR bar" --raw --json
```

## `clep tree`

```text
clep tree [--json]
```

Walks the configured vault. Indexed notes include kind, title, tags, and word
count; other files include size. Dotfiles and `.clepsydra` are hidden. `--json`
emits machine-readable output. Config, vault, index, and traversal failures
return `1`.

## `clep version`

Prints the package version followed by a newline. It is equivalent to
`clep --version`.

```bash
clep version
```

## Typical workflow

```bash
clep init ~/vault
clep config create
# Edit the selected config and set [vault].root = "~/vault".
clep doctor
clep serve
# From another terminal:
clep new "Research log"
```
