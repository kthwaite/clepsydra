The HTTP API is served by `clep serve`. Initialize a vault, select it with the
normal application `config.toml`, and start the server before calling these
operations. Use `http://` unless TLS is enabled in `[server.tls]` or with
`clep serve --tls`; then use `https://`. The client must both trust the
configured or generated certificate's issuer and use a hostname or IP address
covered by that certificate. Build the client origin from that reachable name
or address and the effective port. A wildcard bind (`0.0.0.0` or `::`) is not a
client destination; substitute a reachable interface address or `localhost`
when calling from the server machine. Enclose an IPv6 literal in brackets, for
example `https://[::1]:3000`.

## Discovery, trust, and errors

- OpenAPI JSON: `GET /api/openapi.json`.
- Interactive Swagger UI: `GET /api/docs`.
- Clepsydra implements no bearer token, API key, session login, or per-operation
  authorization layer. Do not invent an `Authorization` header. Network
  reachability is the API trust boundary; keep the default loopback host unless
  access is constrained by a separately controlled network boundary.
- JSON request bodies use `Content-Type: application/json`; the BibTeX import
  uses `text/plain`, attachment upload uses `multipart/form-data`, event delivery
  uses server-sent events, and blob/attachment reads return bytes.
- Attachment upload requires multipart fields `file` and
  `plaintext_acknowledged=true`. Attachment bytes, names, paths, MIME types, and
  sizes remain plaintext even when referenced by a protected page. The
  acknowledgment records disclosure; it does not encrypt or authorize the
  upload. See [Attachments and Media](/docs/attachments-and-media).
- Documented JSON errors contain `{ "status": 409, "error": "..." }`.
  `detail` and `hint` appear only when the error supplies them. The status lists
  below come directly from the application OpenAPI document.

Path values are vault-relative and must be URL-encoded when substituted for a
`{path}` parameter. Successful writes can return `201 Created`, `202 Accepted`,
or `204 No Content`, not only `200 OK`. Revision-bearing mutations reject stale
clients with `409 Conflict`; fetch the current resource and retry deliberately.

## Examples

```bash
# Server health/data request
curl http://127.0.0.1:3000/api/vault/uptime

# Search (URL-encode query values)
curl "http://127.0.0.1:3000/api/vault/index/search?q=water%20clock&limit=20"

# Create a page in the configured default page folder
curl -X POST http://127.0.0.1:3000/api/vault/pages \
  -H "Content-Type: application/json" \
  -d '{"title":"Research log","body":"First observation"}'

# Upload plaintext attachment bytes (acknowledgment is mandatory)
curl -X POST http://127.0.0.1:3000/api/vault/attachments/images%2Fclock.jpg \
  -F "file=@clock.jpg" \
  -F "plaintext_acknowledged=true"
```

For exact request and response schemas, defaults, parameter locations, and live
examples, use the OpenAPI JSON or Swagger UI exposed by the same running binary.
The canonical inventory below remains stable and searchable in this guide.
