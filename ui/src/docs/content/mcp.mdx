`clep mcp` is a stdio Model Context Protocol server for agent hosts. It does
not open the vault itself: every `vault_*` tool proxies to the HTTP API of a
running `clep serve`, preserving that server’s revision checks, path locks,
link rewrites, hooks, folder projection, and event notifications.

## Prerequisites

1. Put `clep` on `PATH`.
2. Select the intended vault with the normal app
   [configuration](/docs/configuration), then start `clep serve`.
3. Register the stdio command with the MCP host. This repository’s `.mcp.json`
   has the required shape:

   ```json
   {
     "mcpServers": {
       "clepsydra": {
         "command": "clep",
         "args": ["mcp"]
       }
     }
   }
   ```

   Claude Code reads a project `.mcp.json`, or can register the same command
   globally with `claude mcp add clepsydra -- clep mcp`. Other MCP hosts need
   an equivalent command/arguments entry.

The MCP process and `clep serve` must resolve the same `config.toml`. Lookup is
`./config.toml` → `$XDG_CONFIG_HOME/clepsydra/config.toml` →
`$HOME/.config/clepsydra/config.toml`. Run `clep config path --trace` when the
selected vault is unclear.

## Workflow

### Connect to the running server

By default, `clep mcp` accepts only a configured loopback host such as
`localhost`, `127.0.0.1`, or `::1`. A non-loopback `[server].host` is refused
because the agent would operate on a remote vault; `clep mcp --allow-remote`
is the explicit override. Bind-all values are still considered non-loopback
for this safety check, even though the HTTP connect target is normalized to
`localhost`.

The URL scheme and port come from `[server]`. Plain configuration uses
`http://<host>:<port>`. When `[server.tls].enabled = true`, MCP uses HTTPS and
adds the configured or auto-generated server certificate as a trusted root.
Start `clep serve` once to generate automatic mkcert files before starting MCP.
TLS verifies the server and protects transport; it does not add an agent login.

### Choose the narrowest tool family

| Family | Tools | Use |
| --- | --- | --- |
| Discover and read | `vault_search`, `vault_get_page`, `vault_list_pages`, `vault_tree`, `vault_links`, `vault_tags` | Locate a page before acting; inspect content, structure, graph, and vocabulary. Oversized `vault_get_page` bodies are truncated and flagged. |
| Create and edit | `vault_create_page`, `vault_update_page`, `vault_edit_page`, `vault_append_page` | Create in one projected mutation; replace whole fields; exact-match a body span; or append to the page/a heading section. |
| Capture | `vault_journal_capture`, `vault_capture_conversation` | Add a fleeting journal entry or capture complete visible conversation turns. |
| Organize | `vault_assign`, `vault_move_page`, `vault_folder` | Declare kind/project, explicitly move a page, or create/move/delete folders. |
| Review and delete | `vault_preview_mutation`, `vault_delete_page` | Preview move/delete link impact, then delete with backlink protection. |

Search before creating. Prefer `vault_edit_page` for a targeted unique body
change, `vault_append_page` for additive capture, and `vault_update_page` only
when replacing a whole field is intentional. Prefer `vault_assign` for
kind/project filing; it computes the projected location. `vault_move_page` is
for an explicit destination that assignment cannot express.

Preview is read-only and is a snapshot, not a reservation. Re-read before the
real mutation. Bulk assignment is all-or-none. Recursive folder deletion is a
separate destructive operation and does not gain page-delete backlink checks
from `vault_delete_page`.

### Capture a conversation

Use `vault_capture_conversation`, not generic page creation. The request
requires a non-blank `title` and a non-empty ordered `turns` array whose roles
are exactly `user` or `assistant` and whose content is complete visible
Markdown. Optional `source_turn_id` and RFC 3339 `timestamp` values must come
from the host. `host_conversation_id` requires `provider`.

The host must supply every complete visible user/assistant turn in source order,
verbatim. Clepsydra cannot fetch missing history and does not accept hidden
prompts, tool traces/results, attachment contents, summaries, or placeholder
turns. With provider plus host ID, later calls append only an exact unseen
suffix; truncated or divergent history conflicts. Without the host ID, every
call creates a new Folio. See
[Codex and Conversation Capture](/docs/codex-and-conversation-capture#capture-or-append-a-visible-conversation)
for Read/Edit and protection behavior.

## Failures and conflicts

- **Server unreachable** — MCP reports the configured base URL and tells the
  agent to start `clep serve`. Confirm the server and MCP process resolve the
  same config, host, port, and TLS mode. Follow
  [Troubleshooting](/docs/troubleshooting).
- **TLS certificate cannot be read or verified** — start the TLS server once so
  automatic certificates exist, or correct both configured certificate paths.
  Do not disable TLS to hide a remote trust failure.
- **`404`** — a page may have moved after assignment. The tool error recommends
  locating it with `vault_search`; do not keep writing the stale path.
- **`409` stale revision** — re-read with `vault_get_page`, reconsider the
  intended change, and retry. Page-write tools send the full-content revision
  they read; the server checks it under the mutation path lock.
- **`409` backlink refusal** — review the returned linking pages with the user.
  Only then rerun `vault_delete_page` with `force: true` and the intended link
  rewrite. This is not an automatic stale-write retry.
- **Validation or protocol error** — invalid paths, kinds, projects, tool
  fields, JSON, or unexpected response bodies are returned to the agent.
  Correct the request rather than guessing.
- **Protected content** — MCP has no unlock, protect, or unprotect tool.
  `vault_get_page` can report metadata and the stored age-armored body, not
  decrypted plaintext. Body edits cannot operate on the hidden plaintext, and
  conversation capture refuses to append to a protected matching Folio.

`vault_append_page` alone performs one targeted stale-write retry. Other
mutations do not silently replay, and no tool should turn an uncertain error
into an assumed success.

## Privacy

The MCP host and its agent can see every tool argument and result. Unprotected
titles, metadata, bodies, search snippets, links, tags, folder names, and
conversation turns are plaintext. They cross stdio between the host and
`clep mcp`, and cross HTTP between `clep mcp` and `clep serve`. Loopback HTTP is
still unencrypted transport; HTTPS encrypts that hop.

The MCP HTTP client sends no bearer token, password, or other application
credential. Loopback reachability is the default trust boundary. Treat every
local process allowed to drive the MCP host and every process able to reach the
configured API as trusted with the accessible vault data. For a remote server,
`--allow-remote` records intent but provides no user authorization; use HTTPS
and a separately controlled network boundary.

Protected Folio bodies remain ciphertext because MCP has no browser decryption
identity. Filenames, paths, titles, tags, projects, encryption descriptors,
conversation provider and ledger hashes, and attachment metadata remain
plaintext. MCP tools do not make unprotected pages, attachments, archives, or
backups encrypted.
