Clepsydra has two separate inbound-web workflows. The browser extension creates
Markdown archive Folios and stores captured resources in content-addressed
storage (CAS). The feed reader keeps subscriptions in `feeds.md` and fetched
entry state in a private local SQLite database. Neither workflow publishes a
website or exposes a public feed.

## Prerequisites

- Start the Clepsydra server and open `/feeds` for the private reader.
- Follow the [Browser Extension](/docs/browser-extension) guide to build and
  connect the capture client. Archiving must be enabled.
- Review `[archive]` settings, especially `cas_path`, path prefix, and request
  limits. The default CAS is `~/.clepsydra/cas`, outside the vault.
- Keep enough storage for vault pages, `.clepsydra/feeds.db`, and CAS blobs.

## Workflow

### Capture a browser page

On a normal `http://` or `https://` page, choose **Capture This Page** in the
extension or use its keyboard shortcut. The extension posts extracted
Markdown, source and canonical URLs, title, capture time, tags, a content
hash, and a self-contained SingleFile snapshot (every reachable resource
inlined as a `data:` URI) to `POST /api/vault/archive`. The server
deconstructs the snapshot and stores its resources in the CAS; the extension
does not hash, split, or upload resources itself.

Configured default tags are always included. The popup's Additional tags field applies only to the capture you are starting and does not change Settings. After capture, ordinary tags can be added or removed from the archived Folio; its captured body and snapshot remain protected.

The Chromium manifest requests `activeTab`, `storage`, `notifications`, and
`scripting`, plus host access for `http://*/*` and `https://*/*`. The Firefox
manifest puts the same HTTP(S) host patterns directly in `permissions` alongside
`activeTab`, `storage`, and `notifications`. This scope lets the injected script
read the current page DOM, lets the background worker relay any cross-origin
resource fetch the content script's own `fetch` cannot make under the page's
CORS policy, and lets it contact the configured Clepsydra server. Review the
captured payload rather than assuming the permissions constrain extraction to
public text or same-origin resources.

The server verifies the Markdown against its declared SHA-256 hash — the only
hash the client declares — then computes its own hashes for the snapshot and
every resource it deconstructs from it, enforces per-blob and total limits,
and creates a non-colliding archive Folio under the configured prefix and
domain. A repeated URL with the same content returns **already exists**
without adding references. A repeated URL with different content returns HTTP
409; the shipped extension only reports **Content Changed** and does not
update or retry the existing archive.

### Understand archive Folios and CAS blobs

The archive Folio keeps its captured title and body read-only while allowing
ordinary frontmatter tags to be amended. Computed tags remain read-only. Its
snapshot and resource bytes live in the separate CAS, keyed as
`sha256:<digest>`. Equal bytes are stored once and their reference count is
incremented. The server can serve a referenced blob from
`/api/vault/cas/<hash>`.

Deleting an archive Folio through Clepsydra removes the Folio and then runs a
post-delete hook that attempts to decrement each distinct snapshot and resource
reference. If that hook fails, the server logs a warning after the Folio
deletion has succeeded; the delete is not rolled back, so leaked reference
counts can retain otherwise unreachable blobs.

A zero-reference blob remains until a CAS garbage-collection call removes blobs
older than the configured minimum age. Although `archive.gc_min_age_days`
exists, no shipped UI or CLI command invokes CAS collection; plan storage and
maintenance accordingly rather than assuming an automatic retention purge.

CAS blobs are not editable note attachments. Attachments are user-managed files
beneath `vault.attachment_folder`, referenced by attachment URLs and deleted
explicitly through the attachment API. CAS blobs are immutable archived bytes,
deduplicated by content hash and reference-counted by archive pages. Changing an
archive Folio's ordinary tags does not edit or replace either kind of byte.

### View an archived snapshot

An archive Folio with a stored snapshot includes a **View archived snapshot**
link. Select it to open the deconstructed SingleFile HTML in the archive viewer.
The viewer banner displays, when present, the optional site name, byline, and
publication time, and provides a back link to the Folio. Use that back link
when you are finished so you return to the same archive context rather than
treating the snapshot as a new page.

The snapshot is displayed in an inert sandbox. Captured scripts do not run,
forms and other active controls do not submit, and links cannot turn the
snapshot into an unrestricted browsing surface. The viewer is for inspecting
the archived bytes, not for resuming the captured site's session or behavior.

The viewer can also explain why it cannot display a snapshot:

- **Missing snapshot** — the Folio has no snapshot metadata, so there is
  nothing to open.
- **Wrong type** — the referenced CAS blob is not HTML and cannot be used as a
  page snapshot.
- **Unavailable snapshot** — the Folio references a snapshot that is no longer
  present in the CAS (for example, after an inconsistent restore or
  garbage-collection mistake).
- **Snapshot availability could not be checked** — a preflight or network
  failure prevented the server from confirming whether the referenced snapshot
  is available. Select **Retry** to check again.

These states do not change the Folio or repair the CAS. Return to the Folio and
use its Markdown and archive metadata while you investigate storage or backup
problems.

The stored deconstructed HTML has a fixed, inclusive ceiling of **2 MiB
(2,097,152 bytes)**. The same ceiling applies at ingest and on both `HEAD` and
`GET`; ingest rejects a snapshot over the ceiling before creating its archive
Folio or CAS entries. This ceiling is distinct from the configurable archive
budgets: `max_blob_size_mb` limits each deconstructed resource, and
`max_request_size_mb` totals the deconstructed HTML, submitted Markdown body,
and deconstructed resources. A request can fit those configurable budgets yet
still be rejected during capture by the fixed HTML ceiling.


### Subscribe and read privately

Open `/feeds`, choose **Manage subscriptions**, and enter an RSS/Atom feed URL
or a site URL from which Clepsydra can discover one. Optional groups organize
subscriptions. The human-readable manifest is `feeds.md`; malformed lines are
reported as diagnostics, and reconciliation preserves the last good
subscription set rather than replacing it with a warning-bearing candidate.

Return to the river and switch among **UNREAD**, **ALL**, and **SAVED**. Filter
by group, feed, or tag. Entry read and bookmark state, cached content, fetch
metadata, and counters live in `.clepsydra/feeds.db`. The scheduler runs an
automatic 60-second due sweep and also wakes when **Refresh feeds** marks
subscriptions due. A success or `304` uses the configured fetch interval, whose
default is a 30-minute base interval. Repeated failures use exponential backoff
from that base, capped at 24 hours.

For an entry with a safe HTTP(S) source URL, **Capture in journal** opens an
editable Markdown draft and appends the submitted text to today’s journal.
The reader stays in place and does not change read or bookmark state. **Copy
link** copies the entry title and source URL as a Markdown link. Neither action
copies the stored article body.

Age retention defaults to 30 days for read entries and 90 days for unread
entries. Quotas retain at most 5,000 entries or 128 MiB per feed and 50,000
entries or 1 GiB globally. Both age pruning and those budgets apply only to
unbookmarked entries. Bookmarked Saved entries are exempt, so Saved storage can
grow beyond the retention budgets; the reader is not a permanent archive unless
you deliberately preserve and back up that growing state.

Subscription edits use a manifest revision. A stale edit, move, delete, or OPML
import is rejected instead of overwriting a newer `feeds.md`; reload and reapply
the intent. OPML import adds subscriptions and maps folders to groups. **Export
OPML** downloads the subscription list only. This is reader interoperability,
not publishing or exporting vault content.

The reader sends outbound HTTP(S) requests to subscribed sites. Its checked
client rejects non-global destinations, disables proxy use, revalidates each
redirect, limits redirects, response bytes, and an absolute request deadline,
and allows only absolute HTTP(S) entry links. These controls reduce SSRF risk;
they do not make remote content trustworthy or private from the publisher.

### Back up and recover shipped state

Run:

```bash
clep backup --destination /path/outside/the-vault
```

The command creates a timestamped uncompressed `.tar`. It walks vault files
without following symlinks, excludes the rebuildable `.clepsydra/cache.db`,
and substitutes a consistent snapshot of `.clepsydra/feeds.db` for its live
SQLite/WAL files. The archive therefore includes ordinary Folios, `feeds.md`,
plain attachments stored inside the vault, and the feed reader database.

The backup does **not** automatically include the default CAS because
`~/.clepsydra/cas` is outside the vault. If `archive.cas_path` points outside the
vault, back up the complete CAS directory, including `cas.db` and the blob tree,
separately and keep that copy consistent with the vault's archive Folios.
Likewise, external Zotero PDF asset paths are outside this backup. If a custom
CAS path is inside the vault, it is walked as ordinary vault content, but that
walk is not a transactional snapshot across archive Folios and CAS.

There is no shipped restore command, archive-import or reference-replay
operation, or CAS refcount rebuild. Recovery means stopping writers, safely
extracting the tar to the intended vault location, restoring a matching complete
CAS directory, including `cas.db`, and restoring any external assets. Start
Clepsydra so the derived page index can rebuild, but do not expect that rebuild
to reconstruct CAS bytes or reference counts from archive Folios. Test this
procedure on a separate location; a backup file's existence alone is not proof
of recoverability.

## Failures and conflicts

- Browser capture is refused when archiving is disabled, a hash is wrong, a blob
  or request is too large, the generated path is invalid, or page publication
  fails. CAS references touched before a later failure are compensated; any
  compensation failure is attached to the primary error and must be investigated.
- HTTP 409 on an existing URL with changed content is non-destructive. The
  shipped extension reports the conflict without updating or retrying; capture
  settings do not currently turn it into replacement behavior.
- Feed discovery or refresh can fail on invalid URLs, non-global destinations,
  DNS, timeout, redirect, response-limit, HTTP-status, or parse errors. The
  existing subscription remains and its error is surfaced for retry.
- Manifest diagnostics preserve the last good subscription set. Fix the exact
  `feeds.md` line before expecting new subscriptions to reconcile.
- Stale feed-manifest mutations return a revision conflict. Reload rather than
  retrying an old revision blindly.
- Backup aborts if it cannot validate or snapshot feed storage, traverse a vault
  entry, or finish the archive. A partial file is not committed as the final
  backup.
- Restoring only vault Markdown leaves externally stored CAS bytes and its
  refcount database absent; archive metadata can then point to missing blobs.
  Restoring only or mismatching CAS leaves no reliable association with the
  restored archive Folios, and startup indexing does not repair that boundary.

## Privacy

Captured pages, URLs, titles, tags, screenshots, resources, and archive Markdown
are plaintext. CAS uses content addressing and deduplication, not encryption;
hashes, MIME types, sizes, and equality can leak information. Browser capture
can include material from authenticated pages, so inspect what was captured and
protect both the vault and CAS directory.

Feed subscriptions in `feeds.md`, cached entry content and reading state in
`.clepsydra/feeds.db`, OPML exports, attachments, and `.tar` backups are also
plaintext. A private reader means Clepsydra does not publish the river; it does
not hide subscription requests from publishers or the network. The project does
not ship public publishing/export from these features, encrypted attachments,
or encrypted backup archives.
