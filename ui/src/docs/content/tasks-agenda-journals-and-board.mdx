Clepsydra derives Todo, agenda, and Task Board views from Markdown in the
vault. Page files remain authoritative; Agenda and the Task Board are indexed
views and mutations over those files, not separate stores.

## Prerequisites

- Run the server and let the vault index finish.
- Open `/agenda` for due Todos and `/tasking` for Project and Cycle planning.
- Use checkbox list items such as `- [ ] Draft proposal`. Inline properties use
  the Markdown form `[due:: 2026-08-14]`, `[scheduled:: 2026-08-13]`, and
  `[priority:: A]`. Write them in Markdown, or set them on a Todo from the
  **Todo properties** popover in Folio
  ([Editor Workflows](/docs/editor-workflows)).
- Todo priority values are `A`, `B`, and `C`, badged `HIGH`, `MED`, and `LOW`
  in Agenda lists and Folio chips. Another value is badged verbatim in
  capitals. Task Board priorities are separate: Critical, High, Medium, and
  Low.
- Enter Todo `due` and `scheduled` values and Cycle start and end values as
  exact `YYYY-MM-DD`. The server does not validate them as dates. For Todos,
  the API compares indexed values lexicographically, so another spelling can be
  misplaced instead of rejected.

## Tasks, Todos, and Checklist Items

A **Task** is a page-backed unit of planned work tracked on the Task Board. A
Task can belong to a Project and a Cycle.

A **Todo** is any Markdown checkbox item, whether it is open, done, or
cancelled. Its status does not change what it is.

A **Checklist Item** is a Todo inside a Task. The Task Board tracks the Task
page as one unit of work and shows progress across its Checklist Items; it does
not treat each Checklist Item as another Task.

## Workflow

### Track Todos and statuses

An unchecked Todo has the persisted status `todo`, `[x]` is `done`, and `[-]`
is `cancelled`. Todo queries can filter by status, due or scheduled bounds,
priority, tag, source page, and whether a due date is absent. Changing a Todo's
status rewrites its checkbox in the source page and then reindexes it.

The status mutation addresses a Todo by source path and indexed byte offset; it
does not verify the Todo's identity at that offset. If an external edit shifts
offsets before reindexing, the endpoint can rewrite a different nearby
checkbox. Wait for reindexing, then reload the page, Task Board, or Agenda
before changing status. Todos inside protected pages are visible only according
to the protected-page index boundary and cannot be changed through the Todo
status endpoint.

### Review the Atrium summary

The Atrium's **Outstanding agenda** shows at most eight open Todos. Dated Todos
come before undated Todos; dated Todos are ordered by ascending `due`, then by
inline priority with `A` before `B` before `C`. Its count is the authoritative
total returned by the Todo query, not merely the number of rows shown. Choose
**Agenda →** or open `/agenda` for the full Agenda surface.

Each row names its source page, and choosing that name opens the page in a
Folio tab. A Todo written underneath another line is indented and carries that
line above it, marked `↳`. The parent is the nearest preceding line at a
shallower indent, whether or not it is itself a Todo — most nesting hangs off a
plain bullet or a heading. The tile orders rows by date and priority across
every page rather than by document position, so a nested Todo usually arrives
without its parent or its siblings; the carried line is the context, not a
tree.

Choose **Stats →** in the Atrium to open `/stats`, which contains the vault
inventory and subjects ranked by frequency.

### Use Overdue, Today, Upcoming, and Undated

Open `/agenda` to review Todos and dated Tasks in one consolidated Agenda.
Agenda shows open Todos plus dated Tasks whose status is not Done:

- **Overdue** contains dated work before today and precedes **Today**.
- **Today** contains work due today, open Todos scheduled today, and open Todos
  in today’s journal. An overdue `due` date wins over both scheduled today and
  membership in today’s journal, so that Todo remains in **Overdue**.
- **Upcoming** contains work due tomorrow through seven days ahead.
- **Undated** contains other open Todos without a `due` property. A no-due Todo
  scheduled for a future day remains **Undated** unless it is contained in
  today’s journal, which puts it in **Today**. A no-due Todo scheduled today
  also belongs in **Today**.

The browser’s local date defines these boundaries.

Change a Todo checkbox or a Task status directly in Agenda. Edit Todo due dates
with **Todo properties** in Folio. Edit Task due dates on the Task Board.
Agenda uses the Task display labels listed below; their persisted status values
remain unchanged.

### Open and capture into journals

Clepsydra keeps two daily journal streams: your own journal (`journals/`, kind
`JOURNAL`) and the AI journal (`ai-journals/`, kind `AI_JOURNAL`) for
agent-initiated notes and work logs. Each stream holds one page per day, keyed
by the same server clock.

Run **Today's journal** from the command palette or choose **Open today’s
journal** in the Atrium for your own journal. Run **Today's AI journal** from
the command palette or choose **AI journal** in the Atrium for the AI stream.
If today's page does not exist, Clepsydra opens the canonical draft path and
creates the page on first write. The server's journal clock decides the
canonical date; the browser constructs the initial draft path from its local
date, so keep client and server clocks aligned.

The journal rail provides **previous entry**, **Today**, **next entry**, and a
14-day recent calendar for the open stream. Previous and next skip unwritten
dates. Only today can be opened as an unwritten draft from that rail; other
journal API lookups accept an exact `YYYY-MM-DD`, not natural-language dates.
Each rail also carries a cross-link row to the sibling stream's page for the
same date — labeled **AI journal** on your journal's rail and **Journal** on
the AI journal's rail — reading **Written · open** when that page exists and
**Unwritten** otherwise.

Run **Capture aside** to append to today's journal. Plain prose becomes a timed
list entry; an existing list item, Todo, heading, blockquote, or code fence
keeps its Markdown shape. `GET /journal/today` also returns open Todos from the
previous seven journal dates as `carried_forward`; it does not copy them into
today's file.

Agent captures into the AI journal follow the same block-shape rule and may
carry an optional short author label after the timestamp, rendered as
`- HH:MM — [author] content`; without an author the entry omits the bracket. An
existing list item, Todo, heading, blockquote, or code fence still passes
through verbatim and unattributed. The AI journal's `today` response carries no
`carried_forward`: Agenda and carried-forward draw only from your own journal,
so AI journal entries and their Todos never appear in Agenda's **Today** bucket
or in a `carried_forward` list.

Neither journal kind can be changed to another kind once assigned, and pages in
either stream cannot join a Project — a journal page's date, not a Project,
organizes it.

### Browse the Calendar

The Calendar places pages on days. A page of kind `JOURNAL` or `AI_JOURNAL`
sits on its journal date, which comes from its `journals/` or `ai-journals/`
filename. A journal page with no journal date falls back to `created_at`. Every
other page sits on the date of its `created_at`, converted to your browser's
local time zone. A page created at 23:30 UTC can therefore sit on the next day
if you are east of UTC.

The index gives `created_at` to a page that has none when it first indexes the
page, and writes it back to the frontmatter. So an imported page without
`created_at` sits on the day Clepsydra first indexed it, not on the day it was
written. Set `created_at` in the frontmatter to move it. A page that still has
no `created_at` in the index is not shown.

**In Folio.** The right rail starts with a **Calendar** section. It shows one
month and follows the open page: it opens on the page's date and marks that
day. Days with pages carry a coloured dot for each kind, up to four. Today has
a ring. Use the previous and next buttons or **Today** to change month.

- The kind menu (the filter button) chooses which kinds the dots and lists
  include. Clepsydra filters on this device only and remembers the choice in
  browser storage. A kind added later is shown by default.
- The collapse button hides the month grid. Clepsydra remembers this too.
- Choose a day to open a popover. It lists that day's pages, grouped by kind,
  with journals first. Choosing a page opens it in a Folio tab and closes the
  popover.
- The popover ends with a journal button. It reads **Open journal** when that
  day's journal exists, and opens it. For today, it also reads **Open journal**
  and opens the draft path, as **Today's journal** does. For any other day
  without a journal, it reads **Create journal**: it creates the journal page
  through `POST /api/vault/journal/{date}` and then opens it. If that request
  fails, Clepsydra shows an error and opens nothing. The button always means
  your own journal, never the AI journal.
- When a month matches more than 5000 pages, the section caption reads
  **5000+** and some days are incomplete.

**The Calendar screen.** Open `/calendar` from **Contents** (under Organise) or
run **Open Calendar** from the command palette. The screen has three modes:

- **Month** shows one month grid. Each day has kind dots and a page count.
- **Months** shows 3, 6, or 12 compact month grids side by side, like a year
  planner. Each day has kind dots only.
- **Weeks** shows 1, 2, or 4 ISO weeks as rows. Each day lists up to eight page
  titles inline; the rest show as "N more" and open through the day panel.

Changing the mode resets the span to its default: 3 for Months, 2 for Weeks.
Choose a day to open the day panel. It holds the same list and journal button
as the rail popover. A day outside the visible range (from a shared link) loads
its own pages. On a desktop the panel sits beside the grid; on a
phone it opens as a bottom sheet.

The filter bar filters by kind (several allowed), one tag, and one project. The
server applies these filters, so the page count and the 5000 cap apply to the
filtered set. When more than 5000 pages match, the screen says it shows the
first 5000; narrow the filters to see the rest.

The screen keeps its state in the URL, so you can bookmark or share a view:

| Parameter | Value |
|---|---|
| `mode` | `month` (default), `months`, or `weeks` |
| `date` | `YYYY-MM-DD` anchor day; default is today |
| `span` | `3`, `6`, or `12` for Months; `1`, `2`, or `4` for Weeks |
| `day` | `YYYY-MM-DD` day whose panel is open |
| `kind` | kind token, such as `NOTE`; several as a comma-separated list, such as `JOURNAL,NOTE` |
| `tag` | exact tag |
| `project` | exact project slug |

An invalid value falls back to the default. Clepsydra drops unknown kinds and
dates that do not exist. The default mode and span are left out of the URL.

### Plan on the Task Board

Open `/tasking` and choose **New task**. Set the Project, status, priority,
Type, Cycle, dates, and optional Description and Checklist. Type defaults to
**None**; pick Feature, Fix, Task, Story, or Spike to classify the Task. The Description becomes
the opening prose in the Task page, above the Checklist, and appears beneath
the title on Board cards. Mark a Task **Blocked** and add a blocker reason when
it cannot proceed.

The Task Board has four views:

- **Board** groups Task cards into **Inbox**, **Ready**, **In Progress**,
  **Review**, and **Done**. Each column header has a tick; the Inbox and Done
  ticks are faint. A card's priority code is toned by rank: Critical in the
  warm hot colour, High in ink, Medium and Low muted. A small dot shows its
  status: cobalt for In Progress, hot for Review, faint for Inbox and Done.
  A typed Task shows its type (`FIX`, `FEATURE`, …) in a small chip after the
  priority; `FIX` is hot, the rest muted. List and Cycles rows show the same
  chip. Done cards have no fill. A blocked Task shows a **Blocked** pill and its
  reason.
- **List** groups Tasks by **Critical**, **High**, **Medium**, and **Low**
  priority. List hides Done (`SEALED`) Tasks by default; the **Show N
  completed** / **Hide completed** toggle beside the view tabs reveals them,
  and the choice persists with the other board settings.
- **Cycles** shows the selected Cycle, its progress, and its Tasks. The strip
  at the top lists every Cycle with its state; choose one to show it, or
  choose **Backlog** for Tasks that are not assigned to a Cycle.
- **Timeline** lays out scheduled Tasks across Projects and Cycles.

The compact toolbar keeps search and view switching above the cards. Open
**Filters** for Project, Tags, priority, Type, status, and Blocked facets.
The Type facet's **Untyped** option matches Tasks with no type. Its badge
counts active facets. **Details** holds Project metadata, active Cycle progress,
and the 14-day completion history without reducing the board's working height.

Open a card in the full-height right-hand editor. The editor's Type row saves at once;
choose **None** to clear the type. On wide workspaces it sits
beside the board, so you can select another card without closing the editor.
On narrower workspaces it overlays the right edge. Its fields scroll separately
from the cards; **Close** or Escape closes it. Pending edits are saved when
closing or switching cards. **Open page** opens the Task's full body and Checklist.

Project labels use the page title rather than its generated filename. Drag the
Scope rail's right edge to resize it, or focus that edge and use the arrow keys
(Home/End select the minimum/maximum width). Double-click the edge to reset its
width. The width persists across reloads and collapsing/reopening the rail.
Long names truncate with the full label available on hover; counts remain visible.
Board columns can also be resized at their right edge, and each column scrolls
independently.

The Scope rail groups Tasks by Project and Cycle, with Backlog for Tasks not assigned to a Cycle.
Every Project page appears in the rail; set `board = false` in a Project
page's frontmatter to hide it. Pages that declare a `project` slug share one
row per slug, and `board = true` breaks the tie when several pages declare the
same slug. Every page's Project — a Task's included — must name a slug that a
Project page declares; the Board, the MCP tools, and the API refuse an unknown
slug. Only a Project page may declare a new slug: give it its `project` slug
first (for example with **Assign** or `vault_assign`), then file Tasks and
other pages under it.
Switching views does not change Task pages. Dragging a card or editing its
panel updates the corresponding Task page metadata.

### Create, start, and close Cycles

Choose the plus control beside **Cycles** in the Scope rail, or **New cycle**
at the end of the Cycles view's strip, to create a Cycle. Set its name,
dates, status, and goal, then choose **Create cycle**. A new Cycle can be
**Planned** or **Active**. In the Cycles view, choose **Start cycle** for a
Planned Cycle or **Close cycle** for an Active Cycle.

When closing a Cycle, choose a carryover outcome:

- **Move to Backlog** removes the Cycle from every Task that is not Done.
- **Move to _next Cycle_** reassigns those Tasks to the selected planned Cycle.
- **Keep in this cycle** closes the Cycle without changing its Tasks.

Closing the Cycle and applying the selected carryover are one atomic server
batch. They are all committed and indexed, or all original Cycle and Task files
are restored. A failed batch emits no successful change notification. Done
Tasks are not carried. This guarantee covers one accepted close request, not
unrelated edits from other clients before or after it.

### Task Board file and API values

Use display labels in conversation and ordinary prose. When editing Task or
Cycle Markdown, or calling the API, use these persisted values:

- Task `status`: Inbox (`INTAKE`), Ready (`TRIAGE`), In Progress (`FIELD`),
  Review (`REVIEW`), and Done (`SEALED`).
- Task `priority`: Critical (`P0`), High (`P1`), Medium (`P2`), and Low (`P3`).
- Task `task_type` (optional): `FEATURE`, `FIX`, `TASK`, `STORY`, or `SPIKE`.
  The API matches it case-insensitively, stores it in capitals, and rejects any
  other value. An absent `task_type` means the Task is untyped.
- Cycle `state`: Planned (`PLANNED`), Active (`ACTIVE`), and Closed (`CLOSED`).
- Backlog is represented in Markdown by an absent `cycle` value. APIs that
  accept a Cycle target use `BACKLOG` to clear the Cycle.
- Over the API an empty or whitespace-only string on a clearable Task Field
  (`cycle`, `assignee`, `estimate`, `task_type`, `due`, `start`, `hold`,
  `link`) clears it, the same as `null`; on create (which has no `hold`) it
  means the field is not set.
- Task `blocked_by` (optional): the Task's Blockers, as a list of wikilinks
  to their codes, for example `blocked_by = ["[[TSK-brave-finch-7q3zd]]"]`.
  Only the waiting Task stores the list. Each entry is a backlink on the
  Blocker's page, and moving or recoding a Blocker rewrites it. Over the API,
  `blocked_by` replaces the whole list: absent keeps it, `null` or `[]` clears
  it, and each entry may be a code, a unique prefix, or `[[CODE]]`. The API
  rejects an unknown or ambiguous code, the Task itself, and a list that would
  close a cycle.
- A Task is Blocked when any Blocker is not Done (`SEALED`) or `hold` is
  non-empty. `hold` stays the free-text blocker reason. A Blocker that reaches
  Done stops blocking, and a Blocker page that no longer exists does not
  block. The board API returns `blocked_by`, the derived `blocks` (the Tasks
  waiting on this one), and the derived `blocked` flag; none of the derived
  values are stored.
- When closing a Cycle through the API, `carry_to: "BACKLOG"` moves unfinished
  Tasks to Backlog, a Cycle code reassigns them, and omitting `carry_to` leaves
  them in place. Tasks whose status is `SEALED` are never carried.

## Failures and conflicts

- Invalid Task statuses, priorities, and relevant Cycle codes are rejected, but
  malformed date strings can instead sort incorrectly. Correct the source
  value, wait for reindexing, and reload the Task Board or Agenda.
- A Todo status update does not reject every stale span: a shifted offset can
  select another checkbox near that byte position. Reindex and reload before
  retrying after external edits.
- A Todo status change returns a conflict for a protected page. Unlock and edit
  the source Folio instead; the endpoint does not decrypt it.
- Task creation can reject a generated destination collision. Existing Task
  and Cycle pages are not overwritten.
- Carryover is valid only while closing a Cycle. The target must be Backlog or
  an existing, different Cycle. Unknown or self-referential targets are
  rejected before the batch starts.
- If any filesystem commit or index step fails while closing a Cycle, the
  atomic batch rolls back the Cycle and every carried Task. Verify the returned
  error, then reload before retrying.
- Agenda and the Task Board are projections. If files were edited outside
  Clepsydra, wait for reindexing or run the documented index recovery before
  treating a stale view as authoritative.

## Privacy

Todos, Tasks, statuses, due dates, Projects, assignees, journal dates, and Cycle
metadata are plaintext in ordinary Markdown and in the local index. Journal
capture is not a private inbox by default. Protect a Folio only when you accept
that protected-page Todo mutation and indexing are deliberately limited.

The shipped work model is local file coordination. It does not provide CRDT or
multi-user collaborative editing; concurrent clients can still race outside the
atomic boundary of one accepted mutation.
