`clep lsp` is a standalone Language Server Protocol process over stdio. It
opens the vault directly, builds a private in-memory index at startup, and
watches the vault so Markdown editors can understand Clepsydra links and
metadata without depending on `clep serve`.

## Prerequisites

- Put `clep` on `PATH` and initialize a vault.
- Open the vault as the editor workspace. An ancestor `.clepsydra` directory is
  the preferred root marker; otherwise the LSP uses the normal application
  [configuration](/docs/configuration) lookup.
- Use an LSP client that negotiates UTF-8 positions. Neovim does this
  automatically; Clepsydra advertises `PositionEncodingKind::UTF8`.

## Workflow

### Configure Neovim 0.11 or newer

Add this to `init.lua`:

```lua
vim.lsp.config['clepsydra'] = {
  cmd = { 'clep', 'lsp' },
  filetypes = { 'markdown' },
  root_dir = function(bufnr, on_dir)
    local root = vim.fs.root(bufnr, '.clepsydra')
    if root then on_dir(root) end
  end,
}
vim.lsp.enable('clepsydra')
```

For Neovim 0.10, start it from a Markdown `FileType` autocmd:

```lua
vim.api.nvim_create_autocmd('FileType', {
  pattern = 'markdown',
  callback = function(args)
    local root = vim.fs.root(args.buf, '.clepsydra')
    if not root then return end
    vim.lsp.start({
      name = 'clepsydra',
      cmd = { 'clep', 'lsp' },
      root_dir = root,
    })
  end,
})
```

For Helix, add the server and extend Markdown in `languages.toml`:

```toml
[language-server.clepsydra]
command = "clep"
args = ["lsp"]

[[language]]
name = "markdown"
language-servers = ["marksman", "markdown-oxide", "rumdl", "clepsydra"]
```

Defining `language-servers` overrides that field, so keep the built-in Markdown
servers you use and append `clepsydra`; do not replace the list with only
Clepsydra. The example preserves Helix’s current Marksman, Markdown Oxide, and
rumdl entries. Check `hx --health markdown` after restarting Helix.

Root resolution checks every workspace folder, then the deprecated `rootUri`,
walking each ancestor chain for `.clepsydra`. If none has the marker, it uses
the same app-config order as the CLI:
`./config.toml` → `$XDG_CONFIG_HOME/clepsydra/config.toml` →
`$HOME/.config/clepsydra/config.toml`, and reads `[vault].root`. Open separate
vaults as separate editor workspaces so each LSP process resolves independently.

### Use the shipped capabilities

| Capability | Shipped behavior |
| --- | --- |
| Completion | `[[` completes canonical page names; `#` completes indexed tags. Inside `+++` TOML frontmatter, declared Base property keys and quoted values complete; relation values use wikilink completion. |
| Hover | Shows the linked Folio’s title, path, and leading body lines, or reports an unresolved link. |
| Go to definition | Opens the resolved wikilink target. |
| References | Returns every indexed wikilink to the page under the cursor. |
| Diagnostics | Reports unresolved and ambiguous links. For plaintext pages, also reports matching Base property type warnings. |
| Code actions | Creates a page for an unresolved link or rewrites an ambiguous link to a selected candidate path. |
| Rename | Returns one editor-applied workspace edit that updates the target title, renames its file, and rewrites indexed referrers. |
| Document symbols | Lists headings in the open document. |
| Workspace symbols | Lists up to 50 indexed pages, filtered by the query. |
| Code lens | Shows an `N references` lens for the current page and resolves it to find-references. |

The LSP process itself never writes vault files. Code actions and rename return
LSP `WorkspaceEdit` operations; the editor applies those file creates, edits,
and renames. Normal buffer saves are also editor writes. If `clep serve` is
running, its watcher sees those external changes and performs any required
folder-follows-metadata reconciliation.

### Understand saves and external edits

`didSave` reindexes the saved path in the LSP’s in-memory index, resolves its
links, clears the document’s dirty flag, refreshes canonical names, and
republishes diagnostics. It does not move a file whose declared kind or project
disagrees with its folder.

An independent filesystem watcher batches changes with a 500 ms debounce,
reindexes them, and republishes diagnostics for open buffers. The watcher does
not replace an editor buffer with externally changed text. Reload a stale open
buffer in the editor before saving it.

When `clep serve` moves a page to reconcile kind/project metadata, the LSP
usually observes a same-filename remove/add pair and logs
`clepsydra: <old> moved to <new> (folder follows kind/project); reopen the file`.
The editor buffer remains attached to the old URI; reopen the new path. If
`clep serve` is not running, folder drift remains until its next startup sweep.

## Failures and conflicts

- **Initialize fails or the client immediately stops** — no workspace ancestor
  contains `.clepsydra` and no app config resolves. Check `:LspLog` and run
  `clep config path --trace` from the editor’s launch directory. See
  [Troubleshooting](/docs/troubleshooting).
- **No `[[` or tag completions** — verify the selected vault root and allow the
  initial index build to finish. Completion only returns indexed canonical
  names and tags that match the typed prefix.
- **A code action or rename is refused** — creation uses no-overwrite semantics,
  rename rejects an existing destination, and an editor may reject unsupported
  resource operations. Re-read the current files before retrying; the LSP does
  not provide the API server’s path locks or revision guard.
- **Diagnostics or references lag an external edit** — wait for the 500 ms
  watch debounce. If the affected file is open, reload it: the index refresh
  does not replace the buffer.
- **A moved buffer is stale** — reopen the logged destination. Automatic client
  buffer retargeting is not shipped.
- **A protected Folio reports `encrypted-body-unavailable`** — expected. The
  LSP retains plaintext frontmatter but suppresses every projection of the age
  armored body, including links, completion, hover content, rename, and Base
  diagnostics for that body.

## Privacy

`clep lsp` is local, uses stdio, and does not call the Clepsydra HTTP server.
It reads the selected vault directly. Every unprotected title, metadata field,
body, link, and tag needed by the index is available in plaintext to the LSP
process and may be returned to the editor in completion, hover, diagnostics,
symbols, references, or workspace edits. The in-memory index is disposable,
not an encrypted cache.

Protected Folio bodies remain age ciphertext and are not indexed by the LSP.
Their filenames, paths, titles, encryption descriptor, and other frontmatter
remain plaintext and visible to the process and editor. Running `clep serve`
beside the LSP does not grant the LSP the browser’s in-memory decryption
identity.

LSP resource operations are trusted local-editor actions. Review rename and
create-page workspace edits before applying them when the editor offers a
preview; they do not pass through the server’s atomic mutation coordinator.
