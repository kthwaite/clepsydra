This guide gets Clepsydra running locally with an initialized vault.

By default, Clepsydra now runs as a **single binary** that serves both:
- the API (`/api/...`), and
- the built frontend (SPA).

## Prerequisites

- Rust toolchain (stable)
- Bun (for `ui/` and `extension/`)
- Optional for local HTTPS: [`mkcert`](https://github.com/FiloSottile/mkcert)

## Workflow

Initialize a vault, point the application config at it, build the embedded UI,
and start `clep serve` (or `cargo run -- serve`). Open `/` for Atrium, create a
first folio, then use Gazetteer and the command console to move between the
corpus-wide and page-focused workflows described below.

## 1) Initialize a vault

From the repository root:

```bash
cargo run -- init ./my-vault
```

This creates:

- `my-vault/.clepsydra/config.toml`
- `my-vault/.clepsydra/templates/`
- `my-vault/_attachments/`

## 2) Create application config

Create (or edit) `config.toml` at the repo root:

```toml
[server]
host = "localhost"
port = 3000
dev_mode = false

[server.tls]
enabled = false
# cert_path = "certs/localhost.pem"
# key_path = "certs/localhost-key.pem"

[vault]
root = "./my-vault"
```

Notes:
- `host = "localhost"` is the default and works best with local TLS certs.
- `dev_mode = false` enables embedded frontend serving.
- `dev_mode = true` disables embedded frontend serving (useful with Vite dev server).

## 3) Build frontend assets for embedding

The backend embeds `ui/dist` into the binary via `rust-embed`.

```bash
cd ui
bun install
bun run build
cd ..
```

> Re-run `bun run build` whenever you want updated frontend assets embedded into the server binary.

## 4) Start Clepsydra (single-binary mode)

```bash
cargo run -- serve
```

Open:

- App: `http://localhost:3000/`
- OpenAPI JSON: `http://localhost:3000/api/openapi.json`
- Swagger UI: `http://localhost:3000/api/docs`

Unknown frontend routes automatically fall back to `index.html` (SPA routing support).

## 5) Optional: Enable localhost HTTPS (`mkcert`)

Set in `config.toml`:

```toml
[server.tls]
enabled = true
# cert_path = "certs/localhost.pem"
# key_path = "certs/localhost-key.pem"
```

Behavior:
- If `cert_path` + `key_path` are provided, Clepsydra uses them.
- If omitted, Clepsydra attempts to run `mkcert` automatically and generate localhost certs.

Generated cert location uses your platform app-data directory, for example:
- macOS: `~/Library/Application Support/clepsydra/localhost.pem`
- macOS key: `~/Library/Application Support/clepsydra/localhost-key.pem`

Then start normally:

```bash
cargo run -- serve
```

Open: `https://localhost:3000/`

## 6) Optional: Expose over Tailscale with Caddy

On macOS, Caddy can serve Clepsydra directly at the machine's fully qualified
MagicDNS name. This avoids placing Tailscale Serve in front of Caddy when
Caddy already owns port 443.

Prerequisites:

- the Mac is connected to the tailnet;
- MagicDNS and HTTPS certificates are enabled for the tailnet; and
- Clepsydra remains bound to `localhost:3000`.

Find the Mac's canonical MagicDNS name:

```bash
/Applications/Tailscale.app/Contents/MacOS/Tailscale status --json
```

Use the `Self.DNSName` value without its trailing dot. For this installation,
the name is `gathering.tail94fed9.ts.net`. Configure
`/opt/homebrew/etc/Caddyfile`:

```caddyfile
clepsydra.localhost {
	reverse_proxy localhost:3000
}

gathering.tail94fed9.ts.net {
	reverse_proxy localhost:3000
}
```

Caddy recognizes the `.ts.net` hostname and obtains its certificate through
the local Tailscale daemon. Validate and reload the active configuration:

```bash
/opt/homebrew/opt/caddy/bin/caddy validate --config /opt/homebrew/etc/Caddyfile
/opt/homebrew/opt/caddy/bin/caddy reload --config /opt/homebrew/etc/Caddyfile
```

Verify the tailnet route and certificate:

```bash
curl -v https://gathering.tail94fed9.ts.net/
```

The request must resolve to the Mac's Tailscale IP, pass certificate
verification, and return HTTP 200. The local
`https://clepsydra.localhost` route remains available.

The MagicDNS name survives restarts, roaming, Tailscale IP changes, and key
renewal. It changes only when the device name or tailnet DNS suffix is
explicitly renamed; update the Caddy site address after either change.

Do not run `tailscale serve` for this topology. Caddy currently listens on
`*:443`, so Serve cannot bind the Mac's Tailscale addresses on port 443.
The macOS extension also rejects the Clepsydra IPv6-loopback proxy target
after normalizing `[::1]:3000` incorrectly. Confirm Serve is inactive with:

```bash
/Applications/Tailscale.app/Contents/MacOS/Tailscale serve status
```

Expected output: `No serve config`.

Security boundary: the `.ts.net` hostname is discoverable through the
tailnet, but this Caddy configuration listens on every local interface.
Tailnet policy governs traffic arriving through Tailscale; it does not block
a client already on the same LAN from connecting directly with the tailnet
hostname. Bind Caddy's tailnet site specifically to the Mac's Tailscale IP if
the LAN is not trusted.

## 7) Optional: Frontend development mode (Vite + HMR)

For active UI development, disable embedded frontend serving:

```toml
[server]
dev_mode = true
```

Run backend:

```bash
cargo run -- serve
```

Run frontend in another terminal:

```bash
cd ui
bun run dev
```

Open the Vite URL (usually `http://127.0.0.1:5173`).

> In `dev_mode`, Clepsydra serves API/docs endpoints only; Vite serves the app shell.

## 8) Create your first page

### Option A: CLI

```bash
cargo run -- new "My first note" --body "Hello from Clepsydra"
```

### Option B: API

```bash
curl -X POST http://localhost:3000/api/vault/pages/notes/first.md \
  -H "Content-Type: application/json" \
  -d '{
    "title": "First note",
    "tags": ["demo"],
    "body": "# First note\n\nCreated via API."
  }'
```

(If TLS is enabled, use `https://localhost:3000/...`.)

## Atrium: your starting dashboard

Open `/` or run **Open Atrium** in the command console. Atrium is the day-start
dashboard: **Open today’s journal** opens or creates the current journal,
**Capture** opens folio inscription, and **Search** opens the command console.
The rest of the dashboard projects current vault state, including inventory
counts and reference-issue access, recent created/edited/opened folios,
activity, frequently used tags, reading and feed panels, and the location-aware
sky panel. These are views over the current server and index; Atrium does not
replace the source Markdown files.

If the sky panel has no coordinates, use its location control or open
**Status → Location**. Clepsydra stores that choice in
`.clepsydra/location.toml`.

## Gazetteer: find and organize the corpus

Open `/gazetteer` or run **Open Gazetteer (index)**. Gazetteer lists the current
content index. Its text filter is a case-insensitive substring match over
title, path, description, and tags. Selecting several tag chips uses AND
semantics, and the sort controls order by update time, path ID, title, or word
count.

On desktop, select visible rows to assign a kind or project in bulk. A
successful assignment can move files because kind and project determine their
canonical paths; rows that failed remain selected so they can be retried. The
mobile view keeps search, tags, sorting, pagination, and page opening, but does
not expose the desktop bulk-assignment bar.

## Filtering

Tasking, Gazetteer, Feeds, the Academic Library, Rubbish, and Agenda share one
filter bar. Where a screen has a text field, it narrows by case-insensitive
substring; **+ FILTER** opens a popover to pick a field and then pick (or
search) its options, and each selection becomes a removable chip. **CLEAR**
resets the text and every facet together. When a screen supplies its total
and currently-matching counts, the bar also shows a trailing **N OF M** once
a filter is active.

Filter state lives in the URL's search parameters, not local component state,
so a filtered view is shareable as a link, restorable on reload, and moves
with the browser's back and forward buttons like any other navigation.

Each screen exposes its own fields over the shared bar:

| Screen | Fields | Text search |
| --- | --- | --- |
| Tasking | Project, Tag, Pri (P0–P3), Status, On Hold | Yes |
| Gazetteer | Kind, Project, Tag | Yes |
| Feeds | Group (including Ungrouped), Feed (narrows to the selected group), Tag | No — use Hide read / Saved instead |
| Academic Library | Type, Status, Year, Tag, queried server-side | Yes — matches title, author, and citation key against already-loaded works |
| Rubbish | Kind | Yes |
| Agenda | Status, Priority (A/B/C) | Yes |

Bases are excluded from this control: a Base's table views define their own
membership and view filters in the Base's TOML definition rather than through
the shared bar. See [Bases](/docs/bases).

## Keyboard shortcut help

Press <kbd>Command</kbd>+<kbd>/</kbd> on macOS or
<kbd>Ctrl</kbd>+<kbd>/</kbd> elsewhere, or run **Keyboard shortcuts** in the
command console. The modal is generated from the current shortcut registry and
groups every active binding by workflow. Notes such as “outside the editor”
identify scope. Press <kbd>Escape</kbd> or dismiss the modal to return to the
current surface.

## Pips and status colours

Small square “pips” carry status throughout the Vessel chrome. They draw
from four signal tokens — **orange** (accent), **cyan** (cool), **amber**
(warn), **red** (hot) — plus the grey ink ramp for neutral states.

### Kind pips

Every page kind has a fixed pip colour, shown in Gazetteer, Constellation,
Sheaf tabs, link previews, and the Folio rails:

| Colour | Kinds |
| --- | --- |
| Orange (accent) | PROJECT |
| Deep orange | BOOK, RECIPE |
| Cyan (cool) | JOURNAL, PERSON, CAPTURE, AI CONVERSATION |
| Amber (warn) | TODO, QUOTE |
| Red (hot) | TASK |
| Ink / greys | CODE (brightest), CYCLE (dimmer), NOTE and ARCHIVE (most muted, shared shade) |

### Board pips (TASKING)

| Pip | Meaning |
| --- | --- |
| Faint grey | INTAKE or SEALED column |
| Grey | TRIAGE column |
| Cyan | IN-FIELD column |
| Amber | REVIEW column |

Cycle pips: outlined box = PLANNED, blinking cyan = ACTIVE, amber =
BACKLOG, faint grey = CLOSED. Operation health dots: cyan = green, amber =
attention, blinking red = critical. Priority chips: P0 red, P1 amber, P2
cyan, P3 grey.

### Dashboard card pips (Atrium)

Card headers carry a pip: pulsing cyan = live and healthy, pulsing orange =
needs attention (for example the Feed river after fetch diagnostics),
static grey = inactive.

### Footer telemetry pips

The VESSEL footer strip shows two pips: the connection pip (cyan =
connected, amber = connecting, red = disconnected from the event stream)
and the write pip, which pulses orange while changes are being sent to the
server.

## Wikilinks

Type `[[` to search for a page, then press Enter or Tab to insert the selected
page. A normal link displays its page title:

```markdown
[[Clepsydra Design Notes]]
```

Add a custom display label after a pipe:

```markdown
[[Clepsydra Design Notes|the design doc]]
```

Only `the design doc` is shown, while the link still resolves to Clepsydra
Design Notes. After completing a page from the dropdown, press Left to move
back into the link and type `|the design doc`. Plain click edits a wikilink;
Cmd-click on macOS or Ctrl-click elsewhere opens it.

## Prefixed external links

In the web editor, provider prefixes expand into ordinary external Markdown
links. Quote values that contain spaces; the closing quote performs the
conversion:

```text
wiki:"Vichy Catalán"
```

Bare values convert when you type Space or Enter:

```text
arxiv:2401.00001
youtube:dQw4w9WgXcQ
youtube:https://youtu.be/dQw4w9WgXcQ
```

Clepsydra uses deterministic labels such as `arXiv: 2401.00001` and
`YouTube: dQw4w9WgXcQ`. Wikipedia targets English Wikipedia. arXiv accepts
identifiers, not full arXiv URLs: use modern `NNNN.NNNN` or `NNNN.NNNNN`
form and legacy `archive/NNNNNNN` form.
Either form may have an optional positive `vN` version suffix. YouTube accepts
video IDs and `watch`, `youtu.be`, `shorts`, and `embed` URLs. Invalid input
stays as typed. Saved pages contain standard `[label](https://…)` Markdown,
not Clepsydra-specific link schemes.

## External resource marks

Clepsydra adds a small decorative mark to recognized external links in the web
UI. The mark is automatic: your Markdown, link label, URL, accessible link
name, and copied text stay unchanged.

For example:

```markdown
[Wikipedia](https://en.wikipedia.org/wiki/Hypertext)
[An arXiv paper](https://arxiv.org/pdf/1706.03762.pdf)
```

Recognized service families include Wikipedia and Wikimedia, arXiv, bioRxiv,
DOI, PubMed, Semantic Scholar, GitHub, GitLab, Internet Archive, YouTube, and
Vimeo. Direct PDF, audio, video, and image links receive file-type marks. A
specific service takes precedence over a generic file extension, so an arXiv
PDF receives the arXiv mark rather than the generic PDF mark.

## Math

Author inline TeX with either dollar or backslash delimiters:

```markdown
Euler's identity is $e^{i\pi} + 1 = 0$.
The same expression is \(e^{i\pi} + 1 = 0\).
```

Author display TeX on its own lines with either delimiter family:

```markdown
$$
\int_{-\infty}^{\infty} e^{-x^2}\,dx = \sqrt{\pi}
$$

\[
\sum_{k=1}^{n} k = \frac{n(n+1)}{2}
\]
```

Click rendered math, or focus it with the keyboard and press `Enter`, to edit
its exact TeX source. If KaTeX cannot render an expression, Folio leaves the
authored delimiters and source visible unchanged so you can repair it.

Folio supports KaTeX-compatible TeX, not complete LaTeX documents or every MathJax extension.

## 9) Optional: Edit the vault from Neovim (LSP)

`clep lsp` starts a standalone language server on stdio — completion for
`[[wikilinks]]`, `#tags`, and frontmatter properties, hover previews,
go-to-definition, link diagnostics, and project-wide rename. It's
read-only and keeps its own in-memory index, so run it alongside
`clep serve`, not instead of it: `clep serve` powers the web UI (and owns
all writes, including folder-follows-metadata moves), while Neovim spawns
and stops `clep lsp` independently.

For typed properties and filtered table views, see [the Bases guide](/docs/bases).

Install the binary and register it (Neovim 0.11+):

```bash
cargo install --path .
```

```lua
vim.lsp.config['clepsydra'] = {
  cmd = { 'clep', 'lsp' },
  filetypes = { 'markdown' },
  root_dir = function(bufnr, on_dir)
    local root = vim.fs.root(bufnr, '.clepsydra')
    if root then on_dir(root) end
  end,
}
vim.lsp.enable('clepsydra')
```

`root_dir` becomes the workspace root the LSP resolves from: it searches
that root's ancestors for a `.clepsydra` directory and, failing that, falls
back to the usual `config.toml` lookup. Because each Neovim workspace sends
its own root, multiple vaults just work without any shared config.

Full capability list, save-time move behavior, and troubleshooting:
`/docs/lsp`.

## Troubleshooting

For common configuration, server, UI, vault initialization, and LSP problems,

## Failures and conflicts

If the UI, server, vault, TLS, or LSP does not start as described, follow
[Troubleshooting](/docs/troubleshooting). Gazetteer bulk assignments use
the server’s typed move operation: successful and unchanged paths are cleared
from the selection, while failed paths remain available for correction rather
than being presented as successful.

## Privacy

Atrium and Gazetteer display server and index projections from the selected
vault. Titles, paths, tags, frontmatter, activity timestamps, and configured
location are not protected by body encryption. Protected folio bodies remain
unavailable to body-derived search and projections, but their plaintext
metadata can still appear. See [Encryption and Protected Pages](/docs/encryption-and-protected-pages)
before treating a dashboard or index as private.
