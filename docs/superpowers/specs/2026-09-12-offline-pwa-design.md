# Offline PWA — design

**Date:** 2026-09-12
**Status:** Merged to develop as 56c0e296 (2026-09-13)
**Scope:** `ui/` (service worker, manifest, offline sync, search fallback, offline UX) and `crates/clep-frontend-assets` (headers, CSP). No API route or DTO changes.

## 1. Why

The UI is served over the tailnet (`https://gathering.tail94fed9.ts.net`). Without cell service or wifi the app is unreachable. The goal is a read-only, installable Progressive Web App on iOS that keeps the **whole vault** (pages, links, navigation views, search) readable offline and stays current whenever a connection exists.

Decisions taken during scoping:

| Question | Decision |
|---|---|
| Offline scope | Read only. Edits are blocked offline; no write queue, no conflict machinery. |
| Coverage | Whole vault, proactively synced. Not just visited pages. |
| Device | iPhone/iPad Safari, installed to the home screen. Desktop and Android work incidentally but get no install polish. |
| Search | Works offline via a client-side index over cached page bodies. |
| Blobs | Attachments and CAS (archived web pages, ~82 MB) are **not** cached. |

Vault today: 252 pages, 1.3 MB of markdown. `ui/dist` is 9.8 MB across 334 content-hashed chunks.

## 2. Architecture

Three cooperating pieces, one store.

```
┌──────────────── page (React) ────────────────┐
│ offline/sync.ts   walker: fills the cache     │
│ offline/search.ts openapi-fetch middleware    │──── fetch() ───┐
│ useOnlineStatus   navigator.onLine ∧ SSE      │                │
└──────────────────────────────────────────────┘                ▼
                                             ┌────── service worker (sw.ts) ──────┐
                                             │ precache: index.html + assets/*     │
                                             │ NetworkFirst /api/vault/* GET       │
                                             │ cache "clep-api-v1" (Cache API)     │
                                             │ miss offline → 503 offline_uncached │
                                             └────────────────┬───────────────────┘
                                                              ▼
                                                        clep serve
```

- The **service worker** is the only offline response source. Every `/api/vault/*` GET goes NetworkFirst; when the network fails or times out, the cached response for that exact URL is returned.
- The **walker** runs in the page and issues ordinary `fetch` calls for the whole vault so the SW records them. It is what turns "visited pages" into "whole vault".
- The **search middleware** synthesises `/api/vault/index/search` answers from cached page bodies when the server is unreachable, because search queries are unbounded and cannot be pre-walked.
- Derived views (board, agenda, tasks, journal, tree, tags) are served offline as their **last-seen** responses. The server remains the only implementation of list/filter/derive logic.

## 3. App shell and install

**Plugin.** `vite-plugin-pwa` 1.3 (peer range includes Vite 8) with `strategies: "injectManifest"`, `srcDir: "src"`, `filename: "sw.ts"`, `registerType: "autoUpdate"`. `injectManifest.globPatterns: ["**/*.{js,css,html,svg,woff2}"]`, `maximumFileSizeToCacheInBytes` raised to cover the largest chunk. Dev: `devOptions.enabled: false`; the SW is only exercised against a production build served by `clep serve`.

**Registration.** `main.tsx` calls `registerSW({ immediate: true })` from `virtual:pwa-register`. Updates apply on next launch (`skipWaiting` + `clientsClaim` in `sw.ts`). No "update available" prompt in v1.

**Manifest** (`manifest.webmanifest`, generated by the plugin): `name`/`short_name` "Clepsydra", `start_url: "/"`, `scope: "/"`, `display: "standalone"`, `background_color` and `theme_color` from the Vessel light palette, icons 192 and 512 PNG plus a maskable 512. Icons rendered from `ui/public/favicon.svg`.

**index.html additions:** `<link rel="apple-touch-icon" href="/apple-touch-icon.png">` (180 px), `<meta name="apple-mobile-web-app-capable" content="yes">`, `<meta name="apple-mobile-web-app-status-bar-style" content="default">`, `<meta name="theme-color">`, viewport gains `viewport-fit=cover`. Layout root pads with `env(safe-area-inset-*)`.

iOS has no install prompt API; the docs page (`ui/src/docs/content/`) gets a short "Install on iPhone" section (Share → Add to Home Screen). Installed PWAs are exempt from Safari's 7-day storage eviction.

## 4. Service worker request policy (`ui/src/sw.ts`)

Same-origin requests only. Evaluated top to bottom:

| Match | Strategy |
|---|---|
| non-GET | network only, never cached |
| `GET /api/vault/events` | network only (SSE) |
| `GET /api/vault/cas/*`, `/api/vault/attachments/*` | network only |
| `GET /api/docs*`, `/api/openapi.json` | network only |
| `GET /api/vault/*`, `GET /api/features` | NetworkFirst, `networkTimeoutSeconds: 4`, cache `clep-api-v1`, `cacheableResponse` statuses `[200]` only |
| navigation request | precached `index.html` (`NavigationRoute` + `createHandlerBoundToURL`) |
| precached asset | CacheFirst from the precache |

Cache key is the full URL including query string, so `/api/vault/pages?limit=200&offset=0` and `/api/vault/pages?limit=50` are distinct entries. The walker uses one fixed query shape per endpoint so its entries are deterministic (§5).

**Miss offline.** When NetworkFirst has neither network nor cache, the handler returns a synthetic `503` with JSON body `{ "code": "offline_uncached", "url": "<request url>" }` and `Content-Type: application/json`. The UI keys on `code`.

No expiration plugin: the walker owns eviction of page-scoped entries (§5, "Prune"). Entries recorded by ad-hoc navigation with query shapes the walker does not know (for example `journal/recent?days=7`) are left in place; they are bounded by what the user actually opens and are cleared whenever the cache name changes. `clep-api-v1` is the cache name; bump the suffix when the entry format changes.

**Pure module.** Route classification (`classifyRequest(url, method): "network-only" | "api" | "navigation" | "asset"`) and the 503 synthesiser live in `ui/src/offline/swPolicy.ts`, imported by `sw.ts`, so vitest covers them without a worker runtime.

## 5. Offline sync walker (`ui/src/offline/sync.ts`)

Runs in the page. Its only side effect is issuing `fetch` calls that the SW records; it does not touch the Cache API directly except to prune.

**Full pass:**

1. `GET /api/vault/pages?limit=500&offset=N` until `items.length < limit`. Collect every `path`.
2. For each path, in parallel with concurrency 6: `GET /api/vault/pages/{path}`, `GET /api/vault/index/backlinks/{path}`, `GET /api/vault/index/outlinks/{path}`.
3. Derived-view set, each once: `/api/vault/folders/tree`, `/api/vault/folders`, `/api/vault/index/tags`, `/api/vault/index/stats`, `/api/vault/index/graph`, `/api/vault/journal/today`, `/api/vault/journal/recent?days=30`, `/api/vault/ai-journal/today`, `/api/vault/ai-journal/recent?days=30`, `/api/vault/board`, `/api/vault/agenda`, `/api/vault/tasks`, `/api/vault/bases`, `/api/features`. The exact query strings mirror what the UI hooks send so the cache entries are hit by real navigation; the implementation plan enumerates them from `ui/src/api/*.ts` and pins them in a single `WALK_SET` table.
4. **Prune:** open `clep-api-v1`, delete any `/api/vault/pages/{path}`, `backlinks/{path}`, `outlinks/{path}` entry whose path is not in the collected set.
5. Record `lastFullSync = now`, `pageCount`.

**Delta pass** (from SSE `index_changed { upserted, removed }`): refetch step 2 for `upserted`; delete cache entries for `removed`; refetch the derived-view set. Deltas are coalesced with a 2 s debounce so a burst of events triggers one pass.

**Triggers:** app launch when online (after a 3 s delay so the first route's own requests win); every `index_changed` event; a "Sync now" button in Settings. A full pass also runs when `lastFullSync` is older than 24 h at launch.

**Guards:** skip when `useOnlineStatus` is false. One pass at a time; a trigger during a pass sets a `rerun` flag. Each request has a 15 s timeout; failures are counted, logged, and do not abort the pass.

**State** (zustand store `useOfflineStore`, persisted to `localStorage`): `phase: "idle" | "running"`, `progress: { done, total }`, `lastFullSync: ISO | null`, `pageCount`, `lastError: string | null`. Shown in Settings ("Offline copy: 252 pages, synced 14:02") and used by the sync indicator (§7).

**Deliberately not done:** no bulk snapshot endpoint. At 252 pages the pass is ~770 small LAN requests. If a full pass exceeds ~30 s on LAN, add `GET /api/vault/pages?include=body` (or a snapshot route) as a follow-up; the walker's shape does not change, only step 2.

## 6. Search fallback (`ui/src/offline/search.ts`)

An openapi-fetch middleware registered on `fetchClient` in `ui/src/api/client.ts`:

- `onResponse`: if the request path is `/api/vault/index/search` and the response is `503` with `code: "offline_uncached"`, return a synthesised response.
- `onError` (network `TypeError` with no SW, e.g. dev mode): same synthesis.

**Index build.** Read every `/api/vault/pages/*` entry from `clep-api-v1` (`cache.keys()` filtered by prefix, then `cache.match`), parse `PageDetailResponse`, feed MiniSearch 7 with fields `title`, `aliases`, `path`, `body`; store `page_id`, `path`, `title`. Options: `prefix: true`, `fuzzy: 0.2`, boost `title: 3`, `aliases: 2`. Skip pages with `encrypted: true`.

**Memoisation.** One index per page session; `sync.ts` calls `invalidateOfflineIndex()` after every pass. Build cost at 1.3 MB is well under a second.

**Response shape.** Array of `SearchResultEntry { page_id, path, title, snippet }`, respecting `limit`. Snippet: first match position in body ± 80 chars, whitespace-collapsed. Ranking differs from FTS5; acceptable.

`/api/vault/blocks/search` (command-palette block search) stays online-only in v1 and shows the offline notice.

## 7. Offline UX

**`useOnlineStatus()`** (`ui/src/hooks/useOnlineStatus.ts`): `navigator.onLine && sseStatus === "connected"`, with `online`/`offline` window events and the SSE status from a small shared store written by `useVaultEvents` (today the hook is per-consumer; it moves its status into a zustand store so both `SyncIndicator` and the editor read one value). SSE "disconnected" counts as offline only after 10 s continuous disconnect, so a server restart does not flip the editor read-only.

**`useVaultEvents` reconnect:** exponential backoff 3 s → 60 s with ±20 % jitter, reset on successful open; no reconnect attempts while `navigator.onLine` is false, resume immediately on the `online` event.

**Sync indicator:** new status "offline". Label: "Offline — vault as of HH:MM" (from `lastFullSync`), or "Offline — no offline copy" when `lastFullSync` is null. Colour: muted, not destructive.

**Editor:** `usePageEditor` returns `readonly: page.readonly || !online`. `Folio` shows a banner "Offline — read only" above the body when the reason is offline, reusing the existing `bodyProtected` rendering path. Pending debounced saves are flushed before the flip when possible; if the flush fails the existing error toast appears and the draft stays in the editor until online returns (no local persistence of drafts in v1).

**Not available offline:** `RouteError` gains a branch for status 503 with `code === "offline_uncached"`: title "Not available offline", body "This page hasn't been synced to this device yet.", a "Retry" button. Query errors with that code do not trigger the generic error toast.

**Mutations:** untouched. An attempt while offline fails at the network and surfaces the existing error toast. Mutation-triggering controls are not hidden in v1.

## 8. Server changes (`crates/clep-frontend-assets/src/lib.rs`)

- `Cache-Control: public, max-age=31536000, immutable` for any path under `assets/`.
- `Cache-Control: no-cache` for `index.html` (both direct and SPA fallback), `sw.js`, `manifest.webmanifest`, `registerSW.js`.
- CSP string gains `worker-src 'self'; manifest-src 'self'`.
- Verify `mime_guess` returns `application/manifest+json` for `.webmanifest`; if not, special-case the extension.

No `clep-api` changes, no OpenAPI change, no `schema.d.ts` regeneration.

**Rust** (`crates/clep-frontend-assets`): unit tests over `static_handler` asserting the three `Cache-Control` classes, the CSP directives, and the manifest MIME type.

**Vitest:**

- `search.test.ts`: fixture cache with three pages → result shape, limit, title boost, encrypted page skipped, memo invalidation.

- `usePageEditor` / `Folio` tests: readonly flips with online status; banner text.
- `RouteError.test.tsx`: offline branch.

**Manual/Playwright:** production build behind `clep serve` with a scratch vault (`CLEPSYDRA__VAULT__ROOT` set); load, wait for full sync, set the context offline, navigate to an unvisited page, search, open board and journal, confirm the editor is read-only; go online, edit, confirm the SSE delta re-caches. One pass on a real iPhone via the tailnet, installed to the home screen, airplane mode.

## 10. Risks and non-goals

- **Plaintext on device.** The whole vault sits in Safari's Cache storage in clear text, protected only by device encryption. Encrypted (`age`) pages cache their ciphertext, as today.
- **Stale derived views.** Board, agenda, journal show the last synced response. The indicator's timestamp is the user's cue.
- **SW update lag.** iOS checks for SW updates on launch; a new deploy is picked up on the second launch after it. Acceptable for a single-user tool.
- **Cache key brittleness.** A UI hook that changes its query string silently stops hitting the walker's entry until the walker table is updated. The `WALK_SET` table and the hooks it mirrors are cross-referenced in one test that imports both.
- **Vault growth.** Walker cost is linear in pages; §5 names the escape hatch.
- **Non-goals for v1:** offline writes or draft persistence, attachment/CAS caching, block search offline, install prompts on Android/desktop, background sync, push.
